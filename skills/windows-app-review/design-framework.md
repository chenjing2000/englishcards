# Windows 本地应用设计框架

**必守**是正确性与交付要求。**默认**用于需求未另行约定的情形。**按需**仅在项目包含相应能力时应用。

| 设计面 | 第一版约定 |
|---|---|
| 使用场景与验收 | **必守** 定义用户入口、主流程、可观察结果和失败后可执行的下一步。新项目及关键改动记录关键决策和验收方式。 |
| 技术与发布 | **默认** 新建常规 Windows 桌面 GUI 使用 C# / WPF，发布 Windows x64 框架依赖版。目标 .NET 主版本按目标电脑和项目需求确定。**必守** 写明 SDK、目标电脑所需的 Windows Desktop Runtime、额外依赖及发布入口。单文件打包和安装方式由项目按需选择。**默认** .NET 程序优先直接使用 `dotnet publish`。需要封装发布步骤时优先使用 `.bat`，尽量避免将 `.ps1` 作为发布入口。 |
| 职责与依赖 | **默认** WPF 采用轻量 MVVM。View 负责布局、焦点、动画等视图行为。ViewModel 在有实际收益时协调命令和界面状态。业务规则、持久化及平台操作按职责分开。跨 UI 或导出入口的共享规则使用同一权威实现。 |
| 数据与兼容 | **必守** 明确用户数据、设置、缓存和输出的路径、归属及覆盖策略。规定数据版本及旧版、损坏文件、外部修改的处理方式。保护用户已有数据，写入失败能定位原因并按契约恢复或重试。 |
| 状态与生命周期 | **必守** 明确状态来源和保存成功的时机。**按需** 定义启动、重复启动、关闭、隐藏、退出、后台任务和取消的顺序及资源释放。 |
| 交互与反馈 | **必守** 规定主流程的确认、错误反馈及恢复操作。**按需** 验证键盘、焦点、窗口缩放和 DPI。涉及真实托盘、登录启动、播放或导出时，在契约卡列出相应实机检查。 |
| 验证与交付 | **必守** 记录从源码到产物的命令、依赖和位置。按影响范围选取业务、集成和界面检查。涉及发布时验证实际产物及用户数据保护，并分别报告自动化和实机证据。 |

## 任务范围与确认门槛

- **讨论或只读审查**按本轮范围提供建议、证据和待定事项。文档落地及代码整改遵循用户授权。
- **按既有契约实施**时，常规且已授权的事项直接执行并验证。已有明确决定的行为、命名、文件组织、控件选择和适用的验证无需重复确认。
- **改变既有契约**时，如果数据格式或迁移策略、主要交互、运行环境或分发方式仍有重要取舍，把待定事项、影响和建议集中请用户决定。用户已明确选择且授权实施的方案直接执行。提交和推送各按项目的授权约定办理。

确认后的具体行为写入项目规格，按需同步 [项目契约卡](project-contract-template.md) 的摘要和验证入口。规则分工见 [手册入口](README.md#规则各自放在哪里)。

触及文件格式或迁移时，写明旧输入如何处理、失败时如何保护原数据、用户如何恢复。验收至少覆盖与本次变更相关的旧输入、失败保护和恢复路径。涉及桌面或文件生命周期时按需读取 [模式库](patterns.md)。

## 现有项目如何应用框架

- 先按[运行与验证形态](runtime-profiles.md)区分桌面 EXE、本地浏览器服务、宿主插件与原型。已有 SDK、宿主和发布契约保留。选择框架依赖发布时，区分开发 SDK、桌面运行时、WebView2 等本机依赖和只在导出时需要的依赖。
- 同时有导入、运行时和导出入口时，明确输入校验、权威数据、派生缓存及产物一致性的证据。对文件格式、媒体文件名、单位或坐标等业务语义，在契约卡引用权威规格与有效示例。
- 采用单 EXE 发布的项目，按需选用[暂存发布](patterns.md#便携程序的暂存发布)。保留已有脚本入口，在项目确实有发布需要时再建立统一入口。
