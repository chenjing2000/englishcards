# Windows 本地应用检查

1. **确定范围。** 从仓库 `AGENTS.md` 找到契约卡、专属检查和验证入口，确认只读审查或整改的授权，检查现有改动。缺少卡片时，查 README、规格与实际入口并标记不确定处。
2. **追踪入口与审查覆盖。** 专项沿受影响的用户入口查到状态、业务、存储及输出，核对直接调用方、失败路径与回归风险。全面审查覆盖主要用例，并检查职责与依赖、行为与数据兼容、状态与生命周期、失败与恢复、测试覆盖。结合项目专属检查和适用的[可复用模式](patterns.md)。

   **结构与可读性**

   - 检查模块职责是否集中、依赖方向是否清楚、主要控制流和状态变化是否容易追踪。抽象、框架和依赖应解决当前问题。关注无用代码、多余层次和难以验证的分支。
   - 允许少量独立的简单重复。优先指出需要同步维护的重复业务规则。高级语法以意图和行为是否更易理解与验证为判断依据，具体说明增加复杂性的地方。
   - WPF 项目按[轻量 MVVM](design-framework.md)检查 View、ViewModel、业务规则与数据访问的边界。结合项目约定判断布局、焦点、动画等视图专属逻辑的归属。
3. **分类发现。** 尽可能给出代码位置、触发条件、可观察影响和证据，区分正确性必修、可靠性与维护性建议、可选风格调整。获准整改时针对根因做最小修正，按[确认门槛](design-framework.md#任务范围与确认门槛)处理待定取舍。
4. **选择验证。** 用项目契约卡的实际命令，按[改动范围和运行形态](runtime-profiles.md#按改动范围选择验证)选择证据。使用样本或隔离数据。
5. **报告结果。** 记录主要发现、获准改动、实际命令和覆盖范围。分别标明通过、失败、跳过、超时及未验证事项。
