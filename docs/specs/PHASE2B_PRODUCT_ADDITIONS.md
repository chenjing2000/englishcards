- Preserve the existing draggable splitter.

## 2. Vocabulary generation Skill

The rule applies to content generated by project Skills. It is not an application-level hard validation rule for user-authored/imported entries.

### 2.1 Single-word entry

A `word` containing exactly one whitespace-separated token must include:

- part of speech;
- British IPA;
- meaning;
- an English example sentence;
- a Chinese translation of that example.

If the same headword has relevant senses under different parts of speech, create separate `senses` entries, each pairing its own POS, meaning, example and example translation. Do not merge different parts of speech into one sense. IPA belongs to the headword and is recorded once, not repeated in each sense.

Hyphens and apostrophes do not split a token. For example, `well-known` and `don't` each count as one word.

### 2.2 Multiword entry

A `word` containing two or more whitespace-separated tokens must not be assigned a part of speech or IPA. Use an empty `pos` in each sense and omit `ipa` or leave it as an empty string.

Each multiword entry must still include:
- meaning;
- English example sentence;
- Chinese example translation.

Examples: `a far cry from`, `take into account`.

### 2.3 Application behavior

- Keep the existing Article v6 Vocabulary schema: `word`, optional `ipa`, `highlight`, and `senses[]`.
- Do not add a `type`, `phrase`, or separate expression collection.
- Do not reject user-imported entries merely because a multiword entry has a non-empty `ipa` or a single-word entry is incomplete. These are Skill content-quality requirements, not parser schema gates.
- Vocabulary list/editor layout is a single vertical column. Each item uses the full available editor width.

## 5. Companion image discovery for JSON import

### 5.1 Search behavior

On every explicit JSON file import:

1. Use the selected JSON file's containing directory.
2. Inspect only that directory's immediate children; do not recurse into subdirectories.
3. Match `.png` and `.jpg` extensions case-insensitively. `.jpeg` is not included.
4. Sort candidate filenames case-insensitively in ascending order.
5. Load only the first matching image.
6. If no candidate exists, import the Article normally and render no image slot.

### 5.2 Data and lifetime

- Do not add an image property, image filename, path, URL or Base64 data to Article v6.
- Do not persist the selected image filename in Article JSON or the automatic Article draft.
- Keep the resolved image as a temporary resource associated with the current JSON import session.
- Preview and PNG/ZIP export must consume the same already-loaded image bytes/resource. Export must not search the directory again.
- On a subsequent explicit JSON import, search again and replace the session image resource.
- On application restart/draft-only recovery, do not invent or infer an image path from Article data. If no live JSON import session exists, omit the image until the JSON is explicitly imported again.
- Release the temporary image resource when the imported Article session is replaced or closed.

### 5.3 Rendering and crop

- Place the image above the English article body.
- Scale to the preview content area's available width, preserving aspect ratio.
- Align image content to the top.
- If the scaled image exceeds the agreed available display height, clip the lower overflow. Do not crop or modify the source file.
- The visible crop is part of the rendered article. PNG/ZIP export must use the same loaded image and the same crop boundary, and must not reveal content hidden in the preview.
- Do not add an image field to Article solely to make export possible. The render request carries the temporary image resource separately from the Article snapshot.

## 6. Workspace toolbar

### 6.1 Position and order

Place a horizontal toolbar in the workspace's upper-right area. Order from left to right:

1. Settings
2. Open JSON
3. Save JSON
4. Export ZIP

The three file-operation buttons retain their existing actions and semantics. This is a relocation and visual restyle, not a behavior rewrite.

### 6.2 Settings

- Replace the old Style tab/page entry with a standalone Settings gear button.
- Clicking the gear opens the existing settings surface/content, adapted to the new presentation. Do not discard existing settings fields or behavior merely because the tab entry is removed.

### 6.3 Visual tokens

- Button surface: 40 × 40 DIP, circular.
- SVG icon: 20 × 20 DIP.
- Button background: `#D3E5EB`.
- Icon stroke: `#27495B`.
- No visible border.
- Hover may slightly darken the button background; keep it subtle.
- Tooltip may show a concise function name.
- Background is a UI button style, not baked into SVG files.

### 6.4 Icon assets

Store four SVG files in:

`EnglishCards/frontend/src/assets/icons/toolbar/`

- `settings.svg` — gear icon;
- `open-json.svg` — open JSON/file icon;
- `save-json.svg` — save JSON icon;
- `export-zip.svg` — ZIP/archive export icon.

SVG viewBox is 24×24; use transparent background, `#27495B` strokes, rounded caps/joins. Do not embed button backgrounds in the SVGs.

## 8. Non-goals and safeguards

- No `illustration` field in Article.
- No image filename/path persistence.
- No recursive image discovery.
- No `.jpeg` support unless separately approved.
- No second toolbar action or changed semantics for existing Open/Save/Export functions.
- No forced 55:45 reset after the user manually resizes the splitter.
- No application-level rejection of Vocabulary entries based only on the Skill's POS/IPA content-quality rules.
- No production UI or persistence changes are included in Phase 2B-0.
