# 数据模型与分页引擎说明

> **历史设计参考，非当前数据契约。** 本文包含早期 schema 3 / V17 结构及 expressions、mainIdea 分区的讨论，已被 Article v6 方案取代。当前数据模型以 [`../architecture/ARTICLE_V6_PHASE1.md`](../architecture/ARTICLE_V6_PHASE1.md) 和 [`../project-contract.md`](../project-contract.md) 为准。本文仅保留分页算法方面仍有价值的技术背景。

## 当前保留的分页设计原则

渲染逻辑区分**逻辑内容结构**与**视觉页面片段**：

- 逻辑正文以完整自然段落为单位；Vocabulary 是独立的文章辅助内容。段落可以被分页器拆成多个视觉片段，但原始 Article 不因分页而切割。
- 基于实际浏览器字体测量宽度和行高；避免孤立代理对、合字、CJK 标点、组合音标与抓取样式丢失。可利用 DOM Range 的 `getClientRects()` 实测每行；HTML/CSS 在预览与导出环境中使用同一套变量。
- 空间不足时从当前已绘制行后准确截断，下一页承接未输出字符；数据流只消费一次。分页器应建立一份所有 page fragment 覆盖原文区间的连续性断言。
- 首行缩进由逻辑自然段起点决定，而不是新页是否有一个 `<p>` 标签决定；续页不能重复首行缩进。
- 尽量避免孤立行，但不能因为孤行控制遗留大空白或删除内容；增加软规则。
- 正文、词汇、译文均应完整保留；不以固定页数限制文章。
- 重点词组不应在视觉上改变行高，重点字号继承正文。强调长词组在正常行断处允许分行，不得强行避免换行导致溢出。

## 仍需保持的回归测试方向

- 很短项目、极长英文句、长中文译文、词汇表多行折行、emoji/组合字符、高亮仅命中第 2 次出现、混合英数和标点。
- 为可分页文本建立 `flatten(pageFragments) == originalText` 断言，确认无吞字、重字或顺序变化。
- 正文与译文 ID 分别使用 `p001`–`p999`；分页内部定位必须区分 `content` 与 `translation` 区域。
